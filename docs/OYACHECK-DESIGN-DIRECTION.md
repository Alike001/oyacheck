# OyaCheck design direction

## Product and boundaries

One continuous interaction: choose English or Naija Pidgin, paste a link/message
or speak, review the words, then deliberately check the evidence. The product
checks suspicious links and forwarded messages. It is not a browser automation
agent, a live reputation scanner or a safety certification service.

Read-only study of the owner's reference landing, onboarding and presence
component showed the value of an obvious voice entry, language choice before
starting, explicit session states, responsive hierarchy and deliberate turn-taking.
Those are interaction principles, not assets or implementation dependencies.
No reference component, shader, font, imagery, layout or brand is imported.

OyaCheck keeps its own self-hosted Lato type, charcoal/deep navy, warm light
reading surfaces and restrained aqua. An original paired-bracket mark frames a
pause/check stroke. Asymmetric headline and interaction areas replace a generic
card grid. Evidence gets a quiet light surface; unknown findings never get a
safe-looking green seal. There is no signup, wallet connection or onboarding gate.

## Original signal indicator

Use small inline SVG: paired open brackets around seven vertical signal marks.
This is authored independently, with no canvas/WebGL/framework dependency.
Only measured microphone RMS changes their height. Zero input stays flat; browser
recognition without exposed PCM has a labelled static listening indicator.
Preparing, analyzing and speaking change labels and static emphasis, not invented
voice amplitude or progress percentages. Reduced motion freezes decorative bar
movement while the separate measured-level bar remains an honest live indicator.
No idle animation, fake speech recognition or fake playback success.

## Main surfaces

- Landing: concise headline, visible language choices, microphone and immediate
  text entry. Link/Forwarded message modes stay explicit. Drafts remain in memory
  through client navigation, never in URL, analytics or browser storage.
- Product proof: user-triggered actual deterministic checks of controlled samples
  and a published NCC advisory hostname. No invented customer examples, scores,
  reviews or anonymized-user claims; no private user dataset is available.
- Checker: same controls and signal language, one vertical reading flow. The
  input folds after a result so the exact risk finding and actual host lead.
- Result: unchanged deterministic label and provenance, concise reasons, next
  steps, visible English/Pidgin explanation, optional Listen/Stop, Check another.
  Technical evidence remains accessible in a disclosure.
- Privacy/limitations: small curated NCC list and URL/message patterns; submitted
  sites are never opened. No threat match does not prove safety. Voice and AI
  are optional; secret-containing transcripts must always be reviewed.

## Reality and acceptance

Keep Ready, Permission, Listening, Transcribing, Reviewing, Analyzing, Preparing,
Speaking, Stopped and Error tied to actual operations. Preserve timeouts,
cancellation epochs, track release and explicit review. Configured credentials
are not provider availability. Browser recognition and server transcription stay
separate from device speech output. Local diagnostics remain opt-in and blocked
on Render. No billable call is authorized by this design task.

The owner confirmed audible TTS previously. Physical capture and genuine
English/Pidgin recognition still require owner acceptance; controlled audio and
mocked provider tests cannot close that gate.

Validate 320, 360, 390, 412, 768 and 1440px, keyboard/focus, reduced motion,
error recovery, drafts/history, controlled input journeys and exact API findings.
Preserve Agent ID 10051, public metadata, registration journals and all financial
locks. Commit locally after checks; no push, deployment, registration or spending.
